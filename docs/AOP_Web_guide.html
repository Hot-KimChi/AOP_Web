AOP Web 사용자 안내서

데이터 조회부터 검증 리포트까지

Flask 백엔드, Next.js 웹 화면, MS-SQL Server를 연결해 측정 데이터 생성·조회·검증·문서화를 지원하는 업무용 애플리케이션입니다.

빠른 이동 프로젝트 개요 기능 안내 기본 사용 흐름 기능별 상세 흐름 실행 방법 로그인·보안 문제 해결

프로젝트 개요

AOP Web은 사용자가 브라우저에서 데이터베이스와 분석 기능을 안전하게 사용하도록 화면과 API를 분리한 풀스택 애플리케이션입니다.

구성역할
Next.js 15 / React 18메뉴, 입력 화면, 데이터 표, 결과 다운로드를 제공합니다.
Flask / Python인증, 데이터베이스 조회, 파일 처리, ML 및 리포트 API를 실행합니다.
MS-SQL Server업무 데이터와 측정·검증 대상 테이블을 저장합니다.
모든 인증 API 요청은 세션 쿠키를 사용합니다. 로그인 후 브라우저를 닫거나 백엔드가 재시작되면 다시 로그인해야 할 수 있습니다.

허용된 데이터베이스와 테이블을 선택해 데이터를 조회합니다. 필요한 경우 별도 데이터 화면에서 필터·정렬·편집·행 삭제·CSV 다운로드를 수행합니다.

SSR DocOut

/SSR_DocOut

Machine Learning

/machine-learning

등록된 모델을 확인하고 학습을 실행합니다. 모델 버전별 성능과 예측 지점을 차트로 비교합니다.

공통 데이터 화면

생성·조회 결과는 데이터 화면에서 공통으로 다룹니다. 열별 연쇄 필터, 정렬, 셀 편집, 행 삭제, 되돌리기, 저장, CSV 다운로드를 지원하며 편집 데이터의 행 정체성을 유지합니다.

기본 사용 흐름

  1. 애플리케이션 접속: 서버 주소의 3000번 포트로 접속합니다. 예: http://서버주소:3000
  2. 로그인: 로그인 창에서 DB 계정과 비밀번호를 입력합니다. 계정 허용 목록이 설정된 경우 허용된 계정만 사용할 수 있습니다.
  3. 기능 선택: 상단 메뉴에서 조회, MeasSet 생성, 검증, SSR 문서 출력, ML 중 필요한 기능을 엽니다.
  4. 조건 입력 및 실행: DB·테이블·프로브·파일 등 필수 조건을 순서대로 선택하고 실행 버튼을 누릅니다.
  5. 결과 확인: 표의 필터·정렬로 결과를 좁히고, 필요한 경우 편집 후 저장하거나 CSV·Word 파일로 다운로드합니다.
  6. 로그아웃: 작업이 끝나면 메뉴의 로그아웃을 사용합니다. 서버 재시작 후에는 보안을 위해 다시 로그인합니다.

기능별 상세 흐름

각 기능은 로그인된 사용자의 브라우저에서 입력값을 확인한 뒤 인증 쿠키를 포함한 Flask API를 호출합니다. 처리 결과는 화면에 표시되며, 필요한 경우 파일로 저장하거나 다음 기능의 입력으로 이어집니다.

1. 홈 · 일정과 내 할 일

업무 시작 전에 일정과 개인 작업을 확인하는 진입 화면입니다.

입력로그인 상태, 새 할 일 제목
처리로그인 상태를 확인하고 계정별 할 일 목록을 불러옵니다. 할 일 추가·완료·삭제는 현재 계정 소유 데이터에만 적용됩니다.
결과SharePoint 주간 일정과 내 할 일 패널이 표시됩니다.
사용 순서로그인 → 일정 확인 → 제목 입력 후 추가 → 완료한 항목 체크 → 필요 없는 항목 삭제

2. MeasSet Generation · 측정 설정 CSV 생성

DB 기준 정보와 업로드 파일을 조합해 측정 설정 데이터를 생성하는 흐름입니다.

입력대상 데이터베이스, 프로브, 생성에 필요한 파일
처리DB·프로브 목록을 조회하고 파일을 서버에 전달해 MeasSet 생성 API를 실행합니다. 생성된 CSV 키로 결과를 다시 조회합니다.
결과생성된 CSV가 표로 표시되고 서버의 1_uploads\0_MeasSetGen_files\ 아래에 저장됩니다.
사용 순서DB 선택 → 프로브 선택 → 파일 선택 → Generate 실행 → CSV 검토 → 새 창에서 편집·다운로드 → 필요 시 SQL 반영
생성 결과를 SQL에 반영하기 전에는 열 값과 행 수를 확인하세요. 표에서 수정한 값은 저장·반영 동작을 실행해야 서버 데이터에 적용됩니다.

3. Viewer · 데이터 조회와 편집

허용된 데이터베이스와 테이블의 현재 데이터를 확인하고 필요한 범위만 다루는 기능입니다.

입력데이터베이스, 테이블
처리서버가 허용 목록을 확인한 후 테이블 데이터를 조회합니다. 데이터 화면은 열별 필터·정렬을 적용하며 현재 열을 제외한 조건으로 옵션을 계산합니다.
결과행·열 데이터가 표시됩니다. 편집본은 행 정체성을 유지하면서 저장하거나 CSV로 내보낼 수 있습니다.
사용 순서DB 선택 → 테이블 선택 → 데이터 보기 → 필터·정렬 → 셀 수정 또는 행 삭제 → 저장/되돌리기/CSV 다운로드

4. Verification Report · Tx 검증 리포트

Tx 요약 파일과 DB의 기준 데이터를 조건별로 대조해 검증 결과를 만드는 흐름입니다.

입력검증 DB, 프로브, Imaging SW 버전, Tx 요약 파일
처리선택 조건에 맞는 DB 데이터를 조회하고 파일 형식·필수 열을 검증한 뒤 Tx 비교 API를 실행합니다.
결과매칭·비교 결과가 화면에 표시되고 검증 리포트가 1_uploads\1_Verification_Reports\ 아래에 저장됩니다.
사용 순서DB 선택 → 프로브·SW 버전 선택 → Tx 파일 업로드 → 파일 미리보기/검증 → 비교 실행 → 결과 확인 및 리포트 다운로드
파일 선택 후 조건을 바꾸면 이전 미리보기와 매칭 결과가 현재 조건과 일치하는지 다시 확인하세요.

5. SSR DocOut · Word 문서 출력

SSR 데이터를 문서 형식으로 정리해 공유하거나 보관하는 기능입니다.

입력데이터베이스, SSR 데이터, 하나 이상의 Meas SS ID
처리선택한 DB의 SSR 테이블에서 대상 행을 조회하고 서버가 Word 문서를 생성합니다.
결과브라우저에서 Word 파일 다운로드가 시작됩니다.
사용 순서DB 선택 → SSR 데이터 로드 → 행 클릭으로 ID 선택 → 선택 항목 검토 → Word 출력

6. Machine Learning · 모델 학습과 평가

등록 모델의 버전과 성능을 확인하고 학습·예측 결과를 비교하는 기능입니다.

입력모델·학습 조건·필요한 데이터 선택
처리모델 목록과 버전 성능을 조회하고 학습 요청을 서버에 전달합니다. 학습 완료 후 성능 및 예측 지점 데이터를 다시 조회합니다.
결과모델 버전별 성능과 예측 산점도가 차트로 표시됩니다.
사용 순서모델 확인 → 학습 조건 입력 → 학습 실행 → 새 버전 확인 → 성능·예측 차트 비교 → 필요 시 버전 정리
학습은 데이터 양과 서버 상태에 따라 시간이 걸릴 수 있습니다. 실행 중에는 중복 학습 버튼을 누르지 말고 완료 상태를 확인하세요.

공통 결과 처리 흐름

  1. 검토: 결과 건수, 필수 열, 오류 메시지를 먼저 확인합니다.
  2. 범위 축소: 필터와 정렬을 사용해 필요한 행만 찾습니다. 필터는 표시만 바꾸며 원본 DB를 즉시 변경하지 않습니다.
  3. 수정: 편집 가능한 화면에서 셀을 바꾸거나 행을 삭제합니다. 실수하면 되돌리기를 사용합니다.
  4. 확정: 저장·SQL 반영·파일 출력처럼 명시된 확정 동작을 실행합니다.
  5. 보관: CSV·Word·검증 리포트를 다운로드하고 업무 규칙에 따라 별도 보관합니다.

실행 방법

Windows 서버에서는 프로젝트 루트의 통합 스크립트를 사용하는 것이 가장 간단합니다.

AOP_Web.bat start      개발 모드 시작
AOP_Web.bat prod       운영 모드 빌드 후 시작
AOP_Web.bat status     백엔드·프론트엔드 상태 확인
AOP_Web.bat restart    재시작
AOP_Web.bat stop       종료
AOP_Web.bat uninstall  Windows 자동 시작 작업 해제

처음 실행하는 경우 백엔드 가상환경과 프론트엔드 의존성을 먼저 준비합니다.

cd backend
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

cd ..\frontend
npm install
운영 모드 주의: AUTH_SECRET_KEY, FLASK_SECRET_KEY, ALLOWED_ORIGINS를 사용자 또는 시스템 환경변수에 영구 등록해야 자동 시작 이후에도 정상 부팅됩니다.

로그인·보안 동작

  • 로그인 성공 후 쿠키에는 불투명 인증 토큰만 저장되며 DB 비밀번호를 쿠키에 저장하지 않습니다.
  • 인증된 API 호출은 쿠키를 포함해 전송되며, 서버는 허용된 DB·테이블 목록과 세션 상태를 확인합니다.
  • 세션에는 만료 시간이 적용되고 요청이 이어지는 동안 유효 시간이 갱신됩니다.
  • 외부 PC에서 접속할 때 API 주소는 브라우저가 실제로 접속한 서버 호스트를 기준으로 자동 계산됩니다.
  • 운영 환경에서는 HTTPS 사용 시 COOKIE_SECURE=true를 설정하고 허용 Origin을 구체적으로 지정합니다.

문제 해결

증상확인할 내용
로그인 창에서 서버 연결 실패AOP_Web.bat status로 5000·3000 포트를 확인하고, 접속 주소에 localhost를 잘못 지정하지 않았는지 확인합니다.
401 또는 로그인 만료백엔드 재시작 여부와 세션 만료 시간을 확인한 뒤 다시 로그인합니다.
데이터베이스 목록이 비어 있음DB 계정 권한, backend\AOP_config.cfg, ODBC Driver 17 설치 여부를 확인합니다.
운영 모드가 시작되지 않음운영 필수 환경변수와 logs\의 시작 로그를 확인합니다.
파일 생성·다운로드 실패입력 파일 형식과 필수 선택값을 확인하고, 저장소 루트의 1_uploads\ 쓰기 권한을 점검합니다.

상태 확인으로 원인을 좁히기 어려우면 scripts\AOP_Web.ps1 -Diagnose를 실행한 뒤 최신 로그를 함께 확인합니다.
